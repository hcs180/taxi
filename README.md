# yoxi Care+｜高齡者規律回診交通服務

給需要固定回診的長輩使用的叫車服務原型。長者、家屬、司機三種身分共用同一份行程狀態：

> 固定回診只設定一次，系統安排好去程、依看診進度建議出門時間；看診延誤時只更新預估，不會替乘客派車；長輩真正看完診，按一個按鈕才開始叫車，司機再依需求接單。

| 用途 | 網址 |
| --- | --- |
| 一般使用 | https://hcs180.github.io/taxi/ |
| 錄影（顯示情境控制器、使用模擬語音） | https://hcs180.github.io/taxi/?demo&simvoice |

錄影步驟見 [DEMO_SCRIPT.md](DEMO_SCRIPT.md)，驗收結果見 [TEST.md](TEST.md)。

## 一、功能

### 長者端
- **首頁四個大按鈕**，依序為：我要去醫院、我要回家、看診當天進度、設定長期預約。「我要去醫院」的叫車視窗只用來去醫院，不再有回家選項。
- **我要回家**：只跳出「上車地點」和「回家地址」兩欄。上車地點自動帶入目前位置（瀏覽器定位後，用 OpenStreetMap Nominatim 查出地址；沒有定位權限時改帶看診醫院的乘車處或請長輩輸入；錄影模式使用標示「模擬定位」的看診醫院乘車處），回家地址帶長期預約的住家，確認後按「確認，馬上叫車」就完成，不用填日期、時間等其他資料；已有回程叫車時直接顯示叫車狀態，不會重複叫車。看診完成後，首頁最上方改成「我好了，一鍵叫車」和「用說的叫車」。
- **長期預約**：填寫醫院、科別、診間、上車地址、每週固定日期、首次回診日期、持續期間（2 週／1 個月／3 個月）、看診或療程開始時間、回診類型和無障礙輪椅車輛需求。
  - 預設值為台大醫院、腎臟內科、3 診、每週一三五、09:00、1 個月，並需要輪椅車輛。
  - 日期由程式依起訖日計算，不寫死筆數。
  - 確認前會預覽所有日期。
- **長期預約管理**：可以檢視所有日期、修改單次、暫停或恢復單次接送、修改整個長期預約，或取消尚未執行的安排。去程數、回程預估需求數、已正式叫車數三者分開顯示。
- **語音輸入**：使用瀏覽器的 Web Speech API（zh-TW）。長期預約也能用說的填上車地址（「從…出發」「地址是…」「在…上車」，說「從家裡」會填入住家地址）；說到選單沒有的醫院時，會提示改從醫院欄位選擇。辨識結果一定先顯示，讓長者確認後才填入，填入後仍可直接修改欄位。
  - 不支援語音、沒有麥克風權限或沒聽清楚時，改用文字輸入；文字會用同一套規則解析。
  - 一般模式**不會**自動套用預設語句。
- **看診當天**頁面顯示：
  - 醫院、科別、診間、日期，以及最近更新時間。
  - 目前燈號和長者號碼。
  - 前方等待號數、預估等待時間、預估輪到、預估看完和建議出門時間。
  - 「估算方式」展開後可以看到完整算式。
- **延誤提醒**：只更新預估時間與司機端的參考需求，並明確顯示「目前尚未派遣回程車輛。」
- **快輪到提醒**（網站內通知）：可以「先登記回程」或「稍後再說」。先登記只記錄需求，不會派車。
- **固定時長療程**（例如透析）：依開始時間與療程長度估算，剩 15 分鐘時提醒。
- **一鍵叫車**：
  - 按下前就顯示已自動帶入的回程資訊：上車地點（看診醫院的指定乘車處）、回程地址（長期預約的住家）、家屬端會同步更新；長輩不用再輸入任何東西，按一下就完成叫車。
  - 防止重複送出：已有進行中的回程時，不會再建立第二筆。
  - 叫車後狀態為「正在尋找車輛」，司機接單後才顯示車牌、車色和預估到達時間。
  - 用說的叫車時，「我好了／我要回家／幫我叫車」辨識成功後會先請長者確認，再建立叫車。
- **單次叫車也能用說的**：在「我要去醫院／我要回家」視窗按「用說的叫車」，說出去哪裡、哪一天、幾點、要不要輪椅車（例如「明天早上八點半從家裡去台大醫院，要輪椅車」）。「從…」會填入上車地點，「去／到…」會填入目的地，「回家」填入住家地址；不在內建清單的地址或院所（例如「從苗栗市中正路100號去為恭醫院」）會照聽到的文字填入，並提醒確認門牌。系統會填入表單並先請長者確認，按「送出叫車」才會叫車。辨識失敗時改用文字輸入。
- **既有功能都保留**：單次回診紀錄、單次叫車（現在也會進入司機任務池）、用車紀錄、字體四段設定、身分切換、經同意的位置分享。
- **照護者語言**：可在設定頁開啟「中文＋Bahasa Indonesia」，提醒和叫車按鈕會同時顯示兩種語言。

### 司機端（操作者為範例司機林志明）
- **未來需求預估**：顯示待命區、待命車輛和預估回程需求，例如「預估 12:00 左右有 1 筆回程需求／狀態：尚未叫車」。這一區**沒有接單按鈕**。
- **正式叫車任務池**：乘客按下叫車後才出現。
  - 列出上車地點、目的地、車輛需求、乘客狀態和任務狀態。
  - 按鈕為「接受任務」和「無法接單，轉給其他待命司機」。
- **轉單**：任務會移出自己的清單，系統重新媒合。其他範例司機約 3.5 秒後接單，接單後才顯示新車輛。
- **目前接送任務**：依序更新為已抵達上車地點、乘客已上車、抵達目的地；有輪椅需求時會提醒協助上下車。
- **已排定的去程任務**：與長期預約同步。
- **未來 24 小時需求分布**：依區域與時段列出需求高低，並在地圖上顯示所選區域。標示為「情境資料」。

### 家屬端
- **長期預約摘要**、目前狀態、延誤資訊、回程叫車狀態，以及車輛和司機資訊。
- **9 步時間軸**：已安排去程、司機已接單、已抵達醫院、等待看診、看診進度延誤、看診完成、已發起回程叫車、司機已接單、已返家。
  - 只有已發生、或由長者／司機操作更新的事件才會打勾。
  - 尚未發生的事件標示「預估」。
- **位置**：只顯示長者在乘車資訊頁主動同意分享的位置；未分享時只顯示院所位置。

## 二、業務規則（程式中的實作位置）

| 規則 | 實作 |
| --- | --- |
| 去程可提前安排 | `cpCreateBooking` 依星期與期間產生每次回診。看診當天依建議出門時間派出去程（`enterVisitDay`）；已派遣的去程時間不會被後續估算自動改掉。 |
| 回程必須由乘客確認才叫車 | 只有 `cpEvents.requestReturn`（一鍵叫車或語音確認）會建立回程叫車。延誤、提醒、登記都不會。 |
| 延誤只更新預估 | `cpDetect`：燈號停滯 20 分鐘以上判定延誤，只寫入 `queue.delay`。回程若已送出叫車，畫面改提示「不會自動修改已送出的叫車」。 |
| N 次回診 ≠ 2N 趟派車 | 長期預約頁分開列出「已安排去程」、「回程預估需求」、「已正式叫車」。 |
| 重複一鍵叫車 | `requestReturn` 先同步狀態，若已在 MATCHING／ACCEPTED／DRIVER_ARRIVING／ONBOARD 就直接返回。 |
| 三端一致 | 三個畫面都只讀 `state`，所有變更都經過 `cpEvents.*`，再寫入 `localStorage`。 |

### 回程狀態機

```text
NO_REQUEST ──先登記──▶ INTEREST_REGISTERED
     │                        │
     └──────一鍵叫車／語音確認──┴──▶ MATCHING（REQUESTED 後立即進入） ──司機接單──▶ ACCEPTED
                                       │  ▲                                        │
                              轉單（重新媒合）│                                     司機到達
                                       ▼  │                                        ▼
                                  MATCH_FAILED ──重新叫車──┘              DRIVER_ARRIVING ─▶ ONBOARD ─▶ COMPLETED
任何等待或已接單（尚未上車）的狀態都可以取消 ─▶ CANCELLED（可以再叫一次）
```

- 回程請求（ReturnRequest）的正式狀態一律由對應的叫車（ride）狀態推導（`CP_RIDE_TO_RETURN`），避免兩份資料不一致。
- ride 狀態依序為 `requested → assigned → arrived_pickup → onboard → completed`，另有 `rematching`、`failed`、`cancelled`。

### 估算公式（簡化版）

```text
等待時間 ＝ 前方號碼數 × 平均每號時間
預計輪到 ＝ 現在時間 ＋ 等待時間
建議出門 ＝ 預計輪到 － 預估車程 － 出門緩衝
預估看完 ＝ 預計輪到 ＋ 看診與領藥時間（＋ 延誤時再加延誤緩衝）
```

情境參數：燈號 18、長者 25 號、平均每號 5 分、車程 20 分、緩衝 10 分、看診與領藥 30 分、延誤緩衝 5 分。

| 時間 | 情境 | 估算結果 |
| --- | --- | --- |
| 10:25 | 前方 7 號 | 等待 35 分，11:00 輪到，11:30 看完，建議 10:30 出門 |
| 10:50 | 燈號仍停在 18 號（停滯 25 分） | 判定延誤：10:50＋35＋30＋5，預估看完改為 12:00 |
| 11:20 | 燈號到 24 號 | 11:25 輪到，預估看完 12:00 |

這些數字都由情境狀態即時計算，不是替換畫面文字。

### 資料模型

存放於 `localStorage` 的 `yoxi-care-senior-pages-v1`。

```text
appointments[]   每次回診：recurringBookingId, hospitalId, department, clinicRoom, date, time/appointmentTime,
                 patientQueueNumber, queueMode, status
rides[]          叫車（等同 DriverTask）：kind(single/return), requestId, pickup, destination, estimatedPickupTime,
                 vehicleRequirement, offeredTo, driverId, status
careplus.bookings[]        RecurringBooking：passengerId, hospitalId, department, clinicRoom, pickupAddress,
                           weekdays, startDate, endDate, appointmentTime, wheelchairRequired, status
careplus.queues{}          QueueStatus：currentQueueNumber, patientQueueNumber, observationTime,
                           estimatedMinutesPerPatient, dataSource, isSimulation…（估算時間由 cpCalc 即時計算）
careplus.returnRequests[]  ReturnRequest：predictedDemandTime, interestRegistered, requestedAt, dispatchedAt,
                           assignedDriverId, wheelchairRequired, status
careplus.outbound{}        每次回診的去程狀態（scheduled / accepted / arrived）
```

**向下相容**：`cpMigrate` 會自動轉換舊資料。
- 舊版 `saved` 叫車改為 `requested`。
- 舊版已派車的叫車補上範例司機。
- 舊版 `careplus.series` 轉為長期預約。
- 原有的回診與字體設定保留不動。

## 五、錄影模式（?demo）

網址加上 `?demo` 會在左下角出現「情境控制」。它只在這個網址出現，一般使用者看不到。

- **重設情境**：清空預約和叫車，填入示範住家地址。
- **載入完整示範資料**：建立長期預約，並直接進入看診當天。
- **看診進度**：進入看診當天、抵達醫院、燈號 +1、延誤（停滯 25 分）、燈號到 24 號、看診完成。
- **療程**：切換一般門診或固定療程、療程剩 15 分。
- **回程派車**：模擬媒合失敗、回程行程下一步。
- **其他**：身分切換（長者／家屬／司機）、照護語言、模擬語音開關。

操作方式：
- 預設「執行後自動收合」，方便錄影時畫面乾淨。
- 「隱藏」可以完全藏起控制器。要再顯示，在電腦上按 `Shift + D`，或在網址加上 `&panel`。
- `&simvoice` 會開啟模擬語音。辨識結果會標示「模擬語音辨識」。

所有控制都呼叫與一般操作相同的 `cpEvents`，只改變情境狀態，不直接改畫面文字。

## 六、部署到 GitHub Pages

1. 把 `index.html`、`assets/`、`README.md`、`DEMO_SCRIPT.md`、`TEST.md`、`.nojekyll` 上傳到 repository 根目錄，並刪除舊的 `assets/careplus.js`。
2. 在 Settings → Pages 選擇 `main` 分支的 `/ (root)`。
3. 這次的 CSS 和 JS 都加上版本參數 `?v=2611j`，避免手機沿用舊快取。之後修改時，請同步更新 `index.html` 裡的版本號。

在本機執行：

```bash
python3 -m http.server 8765
# 開啟 http://localhost:8765/?demo&simvoice
```

## 七、限制

- **沒有後端**：沒有真正的醫院 API、車隊 API、推播、排程或跨裝置同步。
- **語音辨識**：需要 Chrome、Edge 或 Safari 等支援 Web Speech API 的瀏覽器，以及麥克風權限；部分瀏覽器會把語音送到瀏覽器廠商的雲端辨識。
- **地圖**：使用 Google Maps 網頁嵌入，不需要金鑰，但可能被部分網路政策阻擋，所以另外提供「在 Google 地圖開啟」連結。
- **附近醫院搜尋**：使用 OpenStreetMap 的公共服務，依序嘗試 Overpass（private.coffee、overpass-api.de）與 Nominatim，每個來源只試一次；這些免費服務在 2026 年常因流量過大回應 429／406，全部忙碌時會提示稍後再試，仍可從範例選擇或自行輸入。資料可能不完整。
- **目前位置**：只有按「我要回家」且同意瀏覽器定位時才取得，經緯度會送到 OpenStreetMap Nominatim 查詢地址，不會存進分享給家屬的位置；室內定位可能有數十公尺誤差，所以一定請長輩確認。
- **個資**：請只輸入虛構姓名與地址。本專案不處理任何真實病歷資料。
